# Physical-device validation

Physical-device evidence is required for claims about touch comfort, sustained performance, thermals and native Android integrations.

## Record before testing

- commit SHA;
- build/artifact identifier;
- device model;
- OS/build;
- renderer/quality tier;
- battery/charging state;
- relevant platform account/test-track state.

## Core acceptance pass

From a cold launch:

1. Open the course-design path.
2. Sculpt terrain with each supported tool.
3. Paint several surfaces.
4. Place/confirm tee and pin.
5. Build/finalize.
6. Enter practice/play.
7. Aim and take representative shots.
8. Save/close/reopen.
9. Confirm the same authored geometry/state returns.
10. Exercise undo/cancel/recovery interactions.
11. Check text/readability and touch-target comfort.
12. Record any accidental input or gesture conflicts.

## Sustained pass

Run the most demanding representative editor/gameplay state for the agreed soak period. Record:

- average and worst perceived/frame metrics available;
- visible hitching;
- thermal/throttling symptoms;
- memory-related failure;
- battery behavior;
- interaction degradation over time.

## Platform-service pass

When applicable:

- purchase;
- restore;
- offline launch after entitlement;
- reconnect;
- integrity request;
- cloud save conflict;
- account deletion/recovery path.

## Result format

A result is PASS only for the exact tested build. Record failures with reproduction steps rather than converting them into "mostly passed."

# Gate 0: ten proof items

Owner: workstream H (this table). Purpose: no Phase 1 build work starts until all ten pass and Nathan signs off (DEC-045). Source: Master Plan, "Phase 0 must prove all of the following before Gate 0 passes".

Status values: `NOT YET RUN` (default), `CODE WRITTEN, NOT YET RUN`, `RUNNING`, `PASS` (evidence file committed and verified), `FAIL` (with a link to the fix task), `WAIVED` (only by a DECISIONS.md entry signed by Nathan). Only the verifier agent or the lead changes a status to PASS, and only after opening the evidence file. As of writing (2026-09-29) nothing has been run: Godot cannot run in the agent sandbox.

Evidence location: CI uploads artifacts named as below and the lead commits the small text/JSON files to `docs/phase0/evidence/gate0/` (videos and logs stay in the CI artifact store or the device-run folder, referenced by a `.txt` pointer with sha256). Every evidence JSON has fields: `item`, `commit_sha`, `godot_version`, `device` (model, OS build), `renderer` where relevant, `date_utc`, `result` (`pass` or `fail`), plus the measurements named below. An evidence file without `commit_sha` does not count.

Devices (DEC-046, supersedes the single-phone reading of DEC-034): two Android phones. The "flagship phone" is Nathan's Samsung Galaxy S22 Ultra (already owned). The "low-end phone" is a cheap Android (Galaxy A14/A15 class, about US$100-150 used) that Nathan still has to buy; its exact model is not yet recorded (open item 1). Wherever a row below says "the benchmark phone", read it as the low-end phone unless the status table in "Status by item" says the flagship is enough. Until the low-end phone exists, items 2, 4 and 9 cannot pass, and item 5 cannot pass its on-device fps part. Performance budgets: 30 fps floor on the low-end phone (p95 frame time under 33 ms, no single frame stall over 100 ms), 60 fps target on mid/high tier phones (DEC-047). Those numbers replace the "p95 <= 40 ms" wording in row 2 and remain placeholders until measured. Other numbers marked (proposed) are budgets from workstream H, to be confirmed by the lead against the real device (PROP-09).

## Gate decision
Gate 0 passes when: all ten rows are PASS or WAIVED-with-decision; the verifier agent has opened each evidence file and checked `commit_sha` values point at commits on trunk; the budget table from item 2 is committed; renderer choice recorded in DECISIONS.md (DEC-035 follow-up); and Nathan says so in writing. On pass the lead records the date, interfaces move from DRAFT to FROZEN, and the schedule is re-estimated (DEC-040).

## If an item fails
Do not lower the criterion silently. Failing item -> a fix task with owner -> re-run -> new evidence file (old one kept, suffixed `_fail_<date>`). Items 2 and 4 may force a renderer change, art budget change or GDExtension decision; item 3 failing forces a math-layer redesign before anything reads the sim.

## Dependencies between items
1 before any device evidence (all device runs use the item 1 install path). 5 and 4 share the item 2 scene. 10 reuses the atomic writer from F and canonical bytes from B and C. 3 (iPhone hash) waits for 8. 7 and 8 need paid accounts (Play $25, Apple $99/yr) which are Nathan's tasks in `docs/phase0/device_runbook.md`.
